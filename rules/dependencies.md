# Библиотеки и решения: лёгкие, быстрые, безопасные

Из подходящих решений выбирать самое лёгкое и быстрое, но только среди безопасных: при
конфликте безопасность важнее веса и скорости.

## Порядок поиска

1. Платформа и стандартная библиотека: PHP и Laravel, Web API и CSS в браузере, .NET BCL.
2. Уже подключённая зависимость.
3. Свой небольшой код с тестами (примерно до 100 строк), если задача узкая.
4. Новая библиотека — только если первые три не подходят и она прошла проверку ниже.

В описании PR указать, что сравнивали и почему выбран этот вариант.

## Проверка новой зависимости

- **Уязвимости:** нет открытых — `npm audit`, `composer audit`, `dotnet list package
  --vulnerable`, osv.dev.
- **Поддержка:** релизы за последние 12 месяцев, пакет не заброшен.
- **Состав:** мало транзитивных зависимостей, нет `postinstall` без нужды.
- **Лицензия:** MIT, BSD, Apache-2.0 или ISC.
- **Вес (веб):** прирост бандла в gzip до/после; ESM с tree-shaking; тяжёлое — лениво.
- **Без UI-китов и CSS-фреймворков:** компоненты свои, на токенах темы.

## Обслуживание

- Версии зафиксированы lock-файлами, в CI — строго по ним (`npm ci`, `composer install`).
- CI проверяет уязвимости: веб `npm audit --omit=dev --audit-level=high`, бэкенд
  `composer audit --locked --no-dev`. Упало — обновить или заменить, а не отключать проверку.
- Ненужная зависимость удаляется в той же задаче.
