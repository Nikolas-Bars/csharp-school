# Учебный контент

## Простые слова при первом упоминании

- Любой термин, который новичок может не знать, при **первом** появлении объясняется простыми
  словами и примером — даже если кажется очевидным: переменная, тип, строка, регистр,
  компилятор, метод, аргумент, индекс…
- Пример: «верхний регистр» — заглавные буквы (A, B, HELLO), «нижний регистр» — строчные
  (a, b, hello). C# их различает, поэтому `hp` и `HP` — две разные переменные.
- Правило действует для теории, задач, подсказок, сообщений об ошибках и для объяснений в чате.
- Аналогии — из игр (здоровье, урон, инвентарь, враги): курс ведёт к Unity.
- Одна новая идея на экран. Короткие абзацы. Обращение на «ты».

## Тесты на каждый урок и модуль

### Для учеников

- Каждая задача урока проверяется автотестами. Сообщение о проваленной проверке объясняет,
  *что* не так и *куда* смотреть, но не выдаёт готовое решение.
- В конце урока — короткая проверка знаний: 2–4 вопроса или мини-задача.
- В конце модуля — контрольная: итоговая задача или проект и тест по всем темам модуля.
  Модуль считается пройденным только после контрольной.
- Подсказки — по шагам (обычно три): намёк → подробнее → почти решение.

### Для самого курса (автоматические)

- У каждой задачи есть эталонное решение и набор типичных неверных решений.
- Тесты платформы проверяют: эталон проходит все проверки, каждое неверное решение падает,
  и падает с ожидаемым понятным сообщением.
- Урок или модуль без таких тестов не считается готовым и не публикуется.
- Где это проверяется: `runner/tests/Content.Tests` (запуск — `make test` в runner, в CI — при
  любом изменении `content/`). Формат файлов — `content/README.md`.
- Код примеров в теории тоже компилируется в тестах: в учебнике не может быть кода, который
  не работает.
