# Ветки задач

Один репозиторий: `backend/`, `frontend/`, `runner/`. Одна задача — одна ветка с трёхзначным
номером (`004`), даже если задача затрагивает несколько частей.

## В начале новой задачи

1. Номер = самый большой `NNN` среди веток (локальных и `origin/*`) + 1. Учитываются и ветки с
   префиксом: `fix-002` — это номер 002. Задачи 001–003 были до общего репозитория: следующая — 004.
2. Есть незакоммиченные изменения — остановиться и спросить пользователя (не stash и не reset
   без спроса). Если чисто — ветка от свежего `main`.
3. Сказать пользователю номер: «Задача 004: ветка создана».

## Пока идёт задача

- Продолжение той же задачи («поправь», «ещё добавь») — та же ветка.
- Ветка без изменений не пушится, PR для неё не создаётся.

## Коммиты, пуши, PR

- **Только после явного подтверждения пользователя.** Сначала ревью (`review.md`), потом
  показать итог и спросить.
- Сообщение коммита — по-русски, что и зачем.
- Сливать в `main` — только по просьбе пользователя, squash.
- Не переписывать запушенную историю (`push --force`, `rebase` опубликованной ветки).
- CI на GitHub (`.github/workflows/`) запускает проверки только той части, что изменилась.
