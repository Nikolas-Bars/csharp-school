# Почему без static

Метод объекта пишут **без** `static`. Слово `static` значит «принадлежит классу целиком, а не
одному объекту». У такого метода нет «своего» героя — значит, нет и его полей:

```text
class Hero
{
    public int hp;

    public static void Heal()
    {
        hp += 10;    // ошибка CS0120: чьё hp? Нужен объект
    }
}
```

Та же ошибка, если вызвать обычный метод через имя класса: `Hero.ShowInfo();` — компилятор не
знает, чью карточку показать. Вызывай через объект: `hero.ShowInfo();`.

Если по привычке написать `static` у метода объекта, будет сразу две ошибки: CS0176 там, где
вызываешь `hero.LevelUp()`, и CS0120 внутри метода. Убери `static` — и обе пропадут.

У методов основного кода `static` по-прежнему значит «не видит переменных основного кода», а у
методов класса — «принадлежит классу, а не объекту».

Бывают и полезные `static`-методы: `Math.Max(3, 8)` вызывают через имя класса `Math`, потому что
ему не нужен объект — он просто считает. А `bag.Add("меч")` — через объект: он меняет именно
этот список.
