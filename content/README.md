# Учебный контент

Курсы — файлами в git: урок меняется через PR, CI проверяет его тестами
(курс C# — `runner/tests/Content.Tests`, английский — `frontend/src/__tests__/englishContent.spec.ts`),
бэкенд загружает в базу командой
`make artisan cmd='course:import'` (все курсы сразу). Правила текста — `../rules/course-content.md`.

## Структура

```
content/
├── courses.json                    # { "courses": ["english", "csharp"] } — папки курсов, порядок на главной
├── english/                        # курс без кода — формат ниже, «Курс английского»
└── csharp/                         # курс: папка = slug
    ├── course.json                 # slug, название, описание (главная), модули по порядку
    └── 01-first-programs/          # модуль
        ├── module.json             # название, описание, уроки по порядку
        └── 01-hello/               # урок
            ├── lesson.json         # название и шаги урока по порядку
            ├── 01-program.ru.md    # экран теории
            └── tasks/hello-world/  # задача
                ├── task.json
                ├── statement.ru.md # условие
                ├── starter.cs      # с чего начинает ученик
                ├── solution.cs     # эталон: проходит все проверки
                └── wrong-*.cs      # типичные ошибки: падают так, как указано в task.json
```

Имена папок — `NN-slug`: номер задаёт порядок только для глаз, порядок в курсе — списки в JSON.
Папка курса называется его slug (`csharp`) — он же в адресе: `/courses/csharp`. Новый курс —
папка с `course.json` и строка в `courses.json`. Курс, убранный из `courses.json`, импорт не удаляет:
на его уроки ссылается прогресс учеников.
Тексты — по языкам: `{ "ru": "…" }`, файлы — `имя.ru.md`. Русский обязателен.

## lesson.json

Шаги трёх видов: `theory` (экран теории — одна идея), `task` (задача из `tasks/<id>`),
`quiz` (проверка знаний в конце урока, 2–4 вопроса). У английского вместо задач — `practice`, а
проверка знаний — упражнения из файла (раздел «Курс английского»):

```json
{ "type": "theory", "text": { "ru": "01-program.ru.md" } }
{ "type": "task", "task": "hello-world" }
{ "type": "quiz", "questions": [{ "question": {…}, "options": [{…}], "answer": 0, "explanation": {…} }] }
```

`kind` — вид урока, необязательно: `lesson` (обычный, по умолчанию) или `test` — контрольная
модуля. Контрольная в модуле одна и стоит последней (папка `NN-module-test`):

```json
{ "title": { "ru": "Контрольная: босс и отряд" }, "kind": "test", "steps": [ … ] }
```

Модуль считается пройденным, когда пройдены все его уроки вместе с контрольной: на карте курса
у него появляется отметка «Модуль пройден», а после контрольной ученик видит поздравление и
ссылку на следующий модуль.

## task.json

- `checks` — проверки runner (`runner/src/Runner.Core/Protocol/Checks.cs`): `output`,
  `variable`, `construct`, `call`, `access` (подробно — ниже).
- `messages` — для каждой проверки, по порядку: что не так и куда смотреть, без готового ответа.
- `hints` — ровно три: намёк → подробнее → почти решение.
- `wrong` — неверные решения: `fails` — номера проверок, которые должны упасть (ровно они),
  или `compileError` — код ошибки компилятора. `why` — что за ошибка, для автора.

## Проверки

```json
{ "kind": "output", "expected": "HP: 100", "stdin": "Аня", "match": "exact" }
{ "kind": "output", "expected": "#\n##\n###\n####", "set": { "height": 4 } }
{ "kind": "output", "expected": "Сумма: 15", "set": { "scores": [5, 9, 1] } }
{ "kind": "output", "expected": "", "set": { "count": 0 } }
{ "kind": "variable", "name": "hp", "type": "int" }
{ "kind": "construct", "construct": "for", "min": 1 }
{ "kind": "call", "method": "System.Math.Max" }
{ "kind": "call", "method": "Program.GetStatus", "caller": "Program.Report" }
{ "kind": "access", "member": "Hero.hp", "min": 1 }
```

- `output` — что печатает программа. `stdin` — что она прочитает через `Console.ReadLine`,
  `match`: `exact` (весь вывод, по умолчанию) или `contains` (текст где-то в выводе).
- `output` + `set` — **второй прогон с другими начальными значениями**: перед запуском runner
  заменяет значение при объявлении переменной (`int height = 3;` → `int height = 4;`). Код ученика
  при обычном запуске не меняется, подмена — только внутри этой проверки. Правила:
  - переменная — из основного кода: объявлена один раз и сразу со значением, не внутри цикла,
    блока `{ }` или метода. Поэтому в стартовом коде её объявляют заранее: `int height = 3;`;
  - значение — JSON-число, строка или `true`/`false`, по типу переменной: `int`, `long` ← целое
    (`5`, не `5.0`); `double`, `float`, `decimal` ← любое число; `string` ← строка; `char` ← строка
    из одного символа; `bool` ← `true`/`false`. Другие типы не подменяются;
  - массив (`int[]`, `string[]`…) и список (`List<int>`…) таких типов ← JSON-массив, каждый элемент
    по правилам выше: `"set": { "scores": [5, 9, 1] }` подменяет `int[] scores = { 3, 4 };`,
    `new int[] { … }`, `new[] { … }`, `new int[2] { … }` (длина берётся из нового списка) и
    `List<int> scores = new List<int> { … };` на `new int[] { 5, 9, 1 }` / `new List<int> { 5, 9, 1 }`.
    Пустой массив `[]` допустим. Двумерные массивы (`int[,]`), массивы массивов и списки списков
    не подменяются. Строки кода не сдвигаются: многострочный `{ … }` превращается в одну строку
    и пустые строки после неё. Подменяется только начальное значение: `scores.Add(7)` ниже
    в коде добавит 7 к новому списку;
  - `Random random = new Random(42)` не подменяется — для зерна заведи переменную:
    `int seed = 42; Random random = new Random(seed);` и `"set": { "seed": 7 }`;
  - не нашлась переменная, нет значения, не тот тип или код с новым значением не собирается
    (например, `const int size = 3;` и `new int[size] { 1, 2, 3 }`) — проверка не проходит,
    программа не запускается, ученик видит, что поправить (`setError` в ответе runner).

  **В задачах с циклами давай вторую проверку вывода с `set`**: иначе засчитается пустой цикл
  `for (int i = 0; i < 0; i++) { }` и готовый ответ в `Console.WriteLine`. Первой ставь проверку
  без `set` — её вывод ученик видит под проверками.
- `expected: ""` — программа ничего не печатает (например, с `set` цикл не выполнился ни разу:
  `"set": { "count": 0 }`). С `match: "contains"` пустой текст есть в любом выводе — так не пиши.
- `variable` — объявлена переменная (регистр важен), `type` — необязательно: `int`, `List<int>`.
- `construct` — конструкция встречается не меньше `min` раз (по умолчанию 1): `if`, `else`, `for`,
  `foreach`, `while`, `doWhile`, `switch`, `method`, `class`, `break` (только выход из цикла —
  `break` в `switch` не считается), `continue`, `constructor` (объявление конструктора класса),
  `property` (объявление свойства), `privateSet` (`private set` у свойства), `this` (слово `this`,
  например `this.hp = hp;`).
- `call` — вызывается метод: полное имя `System.Console.WriteLine`, свои методы — `Program.Имя`.
  `caller` — необязательно: вызов засчитывается, только если он внутри этого метода
  (`Program.Report`, метод класса — `Hero.Heal`), конструктора (`Hero.Hero` — имя класса дважды) или
  свойства (`Hero.Hp` — в `get` или `set`) — прямо в теле, во вложенном методе или лямбде внутри него. Вызов из
  основного кода тогда не считается. Методы сравниваются по имени: перегрузки (несколько методов
  с одним именем и разными параметрами) не различаются.
- `access` — значение поля или свойства читается не меньше `min` раз (по умолчанию 1): `member` —
  класс и имя, `Hero.hp`. Чтение — `hero.hp`, `this.hp` или `hp` внутри класса; запись (`=`, `+=`,
  `++`) не считается. Ловит печать исходной переменной вместо поля объекта:
  `Console.WriteLine(hp)` вместо `Console.WriteLine(hero.hp)`.

## Что проверяют тесты

Эталон компилируется и проходит все проверки; стартовый код компилируется (или пуст — ошибка
CS5001) и не проходит;
каждое неверное решение падает ровно так, как указано; весь код ` ```csharp ` в теории и
условиях компилируется; ссылки на файлы и задачи существуют, лишних полей нет, у каждой
проверки есть сообщение, подсказок три, вопросов 2–4; каждый модуль заканчивается своей
единственной контрольной (`"kind": "test"`).

## Курс английского

Тот же «курс → модули → уроки», только вместо задач с кодом — упражнения. Проверка ответа — в
браузере ученика, функцией `frontend/src/utils/answers.ts`; та же функция проверяет контент в тестах.

```
english/01-simple-tenses/01-present-simple/
├── lesson.json
├── 01-when.ru.md                   # теория: одна идея на экран
├── practice/form.json              # упражнения практики
└── quiz.json                       # проверка знаний: 2–4 упражнения, последний шаг урока
```

Шаги урока — `theory`, `practice` (засчитывается по `id`, как задача C#) и `quiz` из файла:

```json
{ "type": "practice", "id": "form", "file": "practice/form.json" }
{ "type": "quiz", "file": "quiz.json" }
```

Файл упражнений — список, у каждого `kind`, задание `prompt` и `explanation` — почему верный
ответ верный (показывается после верного ответа и рядом с показанным ответом). Английские фразы
(варианты, плитки, ответы) пишутся строкой, тексты для ученика — по языкам:

```json
{ "kind": "choice", "prompt": { "ru": "Как сказать «Я сейчас читаю»?" },
  "options": [{ "text": "I read now.", "why": { "ru": "Это Present Simple — про «обычно»." } },
              { "text": "I am reading now." }],
  "answer": 1, "explanation": { "ru": "I → am, к глаголу -ing." } }

{ "kind": "gap", "prompt": { "ru": "Вставь глагол." }, "text": "She ___ (cook) dinner now.",
  "accept": ["is cooking"], "mistakes": [{ "answer": "cooks", "why": { "ru": "now — сейчас." } }],
  "hint": { "ru": "am / is / are + -ing." }, "explanation": { "ru": "she → is, к глаголу -ing." } }

{ "kind": "order", "tiles": ["doing", "you", "What", "do", "are"], "accept": ["What are you doing"], … }
{ "kind": "translate", "text": { "ru": "Я не смотрю телевизор." }, "accept": ["I am not watching {TV|television}"], … }
{ "kind": "fix", "text": "She are waiting.", "wrong": 1, "accept": ["is"], … }
```

- `choice` — 2–4 варианта; у каждого неверного `why` — почему он не подходит, у верного `why` нет.
- Остальные — ответ словами: `accept` — правильные ответы, `mistakes` — частые ошибки и объяснение
  каждой, `hint` — для любого другого неверного ответа, без готового ответа.
  - `gap` — один пропуск `___` в английской фразе, в скобках можно дать глагол: `(cook)`;
  - `order` — плитки в порядке показа (не в порядке ответа), лишние — для ловушки; плитка может
    быть из нескольких слов: `"on weekends"`;
  - `translate` — фраза по-русски (`text` — только `ru`), перевести на английский;
  - `fix` — номер слова с ошибкой `wrong` (слова через пробел, с 0) и правильная замена.
- Как сравниваются ответы: регистр, лишние пробелы, знаки препинания и вид апострофа не важны;
  краткие и полные формы равны (`don't` = `do not`, `'s` = is / has, `can't` = `cannot`); опечатки не
  прощаются. `{a|b}` в ответе — любой из вариантов, `{a|}` — необязательное слово. `"forms": "exact"`
  — краткая и полная форма различаются (задание «напиши краткую форму»).
- Ошибся — объяснение именно этой ошибки; после второй неудачи ученик видит правильный ответ и
  должен сам выбрать или ввести его, чтобы пройти дальше.

### Теория английского

Сверх обычного Markdown:

- таблица `| a | b |` со строкой-разделителем `|---|---|` — формула времени; `**жирным**` — то,
  что меняется (am, -s), первая колонка — заголовок строки;
- `==now==` — слово-маркер, выделяется;
- `> текст` — заметка («Сравни:», «Подсказка:»);
- пример со звуком — ученик слушает фразу (американский голос браузера):

  ````
  ```example
  Look! It is raining.
  Смотри! Идёт дождь.

  She works in a hospital.
  Она работает в больнице.
  ```
  ````

- частая ошибка — неверно (зачёркнуто), верно, почему:

  ````
  ```mistake
  He work in a bank.
  He works in a bank.
  He — значит, к глаголу нужно -s.
  ```
  ````

Примеры и ошибки в одном блоке разделяются пустой строкой.

### Что проверяют тесты английского

Каждый правильный ответ (со всеми `{a|b}`) проходит; каждая частая ошибка неверна и показывает своё
объяснение; ошибка не совпадает с правильным ответом; ответы `order` собираются из плиток, а плитки
по порядку показа — ещё не ответ; у неверных вариантов `choice` есть объяснение; в английских фразах
нет кириллицы; у примеров и ошибок в теории есть перевод и объяснение; лишних полей нет; проверка
знаний — последний шаг, 2–4 упражнения; контрольная в модуле одна и последняя. Тест сообщает все
найденные проблемы разом. Запуск — `make test` во `frontend` (контейнер видит `../content`).
